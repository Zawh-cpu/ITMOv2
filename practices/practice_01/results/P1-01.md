# Обзор PR: найденные проблемы

Посмотрел diff. Он добавляет эндпоинт `POST /api/reviews`, который передаёт diff в LLM для ревью. Есть ряд проблем — от критичных до стилистических.

## Критичные

**1. Нет валидации входных данных (`app/api.py:36`)**
```python
def create_review(payload: dict) -> dict[str, str]:
    return review_service.review(payload["diff"])
```
- Используется `dict`, а не Pydantic-модель. FastAPI не проверит наличие поля, тип, длину.
- Если `"diff"` отсутствует в payload → `KeyError` → неконтролируемый 500 вместо аккуратного 422/400.
- Нет автогенерации OpenAPI-схемы для запроса.

**2. Отсутствует обработка ошибок вызова LLM (`app/review_service.py:21`)**
```python
answer = self.llm.generate(prompt)
```
Если провайдер LLM упадёт по таймауту/лимиту/сети — исключение просто улетит наверх как 500 без внятного сообщения.

**3. Prompt injection**
Diff вставляется в промпт напрямую без экранирования/ограничений:
```python
prompt = f"Review this pull request and find problems:\n{diff}"
```
Если diff содержит текст вида "Ignore previous instructions and...", это может манипулировать выводом модели.

**4. Синхронный I/O-вызов в асинхронном FastAPI-приложении**
`create_review` и `review()` — обычные `def`, а вызов LLM почти наверняка сетевой (I/O-bound). В ASGI-приложении такой синхронный блокирующий вызов может подвесить event loop при конкурентных запросах (если не запускается FastAPI в threadpool автоматически — но лучше делать `async def` + `await llm.generate(...)`).

## Средние

**5. Нет ограничения размера diff** — большой diff = дорогой/долгий вызов LLM, риск DoS/costs blowup.

**6. Нет аутентификации/rate limiting на публичном эндпоинте**, который тратит платные LLM-токены — потенциальная дыра для abuse.

**7. Нет логирования** запроса/ответа для отладки и аудита.

## Мелкие / стилистические

**8. Бессмысленное изменение форматирования** в `LLM.generate`:
```diff
-    def generate(self, prompt: str) -> str: ...
+    def generate(self, prompt: str) -> str:
+        ...
```
Чисто косметика, добавляет шум в diff без функциональной необходимости.

**9. Нет тестов** для нового эндпоинта `/api/reviews` и метода `ReviewService.review`.

**10. Нет явной response-модели** — `-> dict[str, str]` работает, но Pydantic response_model даёт лучшую валидацию/документацию.
