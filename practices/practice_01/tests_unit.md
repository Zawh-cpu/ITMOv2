# Unit-проверки

Объект: `ReviewService.review` и `create_review` из `TRAINING_PR.diff`. Исходников сервиса в репозитории нет, только diff, поэтому проверки описаны по нему; запуск не выполнялся. Допущение: используется pytest и подставная реализация `LLM` (fake, запоминает prompt и возвращает заданную строку).

| Требование или правило | Что проверяем изолированно | Вход | Ожидаемый результат | Подтверждение |
|---|---|---|---|---|
| U1. `review` возвращает ответ LLM | `ReviewService(fake_llm).review(diff)` | fake отвечает "ok", diff "x" | `{"comment": "ok"}` (по diff, строка 16 `return {"comment": answer}`) | pytest, сравнение результата |
| U2. Diff попадает в промпт | Промпт, переданный в `llm.generate` | diff "DIFF-123" | prompt равен `"Review this pull request and find problems:\nDIFF-123"` (по diff, строка 14; в TO BE будет промпт по master prompt, допущение) | pytest, проверка `fake.last_prompt` |
| U3. Вызов LLM ровно один | Счётчик вызовов | любой diff | `fake.calls == 1` | pytest |
| U4. Сбой LLM (текущее поведение) | `review` при исключении в `generate` | fake бросает `RuntimeError` | Исключение пробрасывается (по diff обработки нет). TO BE: контролируемая ошибка (допущение) | pytest `pytest.raises` |
| U5. Нет поля `diff` (текущее поведение) | `create_review({})` вызовом функции | `{}` | `KeyError` (по diff `payload["diff"]`). TO BE: контролируемая ошибка (допущение) | pytest `pytest.raises(KeyError)` |
| U6. Пустая строка diff | `review("")` | `""` | Поведение не определено в diff; требование к нему неизвестно (вопрос владельцу). Пока фиксируем: вызов LLM происходит с пустым diff в промпте | pytest, фиксация текущего поведения |
| U7. Формат отчёта (проверка ответа модели, допущение: скрипт-чек-лист вне diff) | Разбор текста ответа | Ответ P1-02 (`results/P1-02.md`) | Есть заголовки "Описание изменения", "Риски", "Проверки"; рисков не больше 3; нет слов approve/merge; нет вопроса в конце; строки рисков: для `app/api.py` 10, для `app/review_service.py` 14 и 15 или «строка не определяется по diff» (допустимы оба варианта, выдуманных строк нет) | pytest на сохранённых ответах или ручной чек-лист |

Тесты U4 и U5 сейчас фиксируют дефекты текущего кода; после исправления (инкремент 3 в [`project_management.md`](project_management.md)) ожидания заменяются на TO BE.
